# Desktop workflow contract

This application combines read-only Grim Dawn equipment analysis with a single-player combat workspace with optional automatic connection that modifies the current game session in memory. Neither workflow directly edits game-save files. The latest request makes every separator extend to its partition edges: main content loses its 1440 px cap and outer padding, fills the workspace and places reading padding inside sections. Retain the canvas top bar/text underline tabs referenced by [analysis-compact.png](artifacts/tauri-ui/screenshots/analysis-compact.png), right-side character/settings, section-local actions and absence of the duplicate contextual toolbar. No directly check-outable Tauri commit for the reference was found; Desktop remains untracked, so this is visual adaptation rather than source rollback. Retain the Card-free layout, shadcn preset `b6HGdE1wo`, Inter/Noto Sans SC, RadioGroup and TanStack/persistent-width improvements. [DESIGN.md](DESIGN.md) owns the current layout; the earlier WPF contract remains in [docs/legacy-wpf-ux.md](docs/legacy-wpf-ux.md).

## Normal workflow

All source directories and the combat executable share editable PathInput controls. Editing alone and blur never save a path; 使用 or Enter explicitly submits it. The 浏览 button always opens a system folder/file chooser, including in local browser development. Confirming the chooser is an explicit apply action; cancelling leaves an unapplied draft intact. Each of the game/save source kinds remembers only its latest path, with no history menu or record-removal action. A successfully accepted source replaces that kind's persisted value; rejected input or cancellation does not replace it. Submission trims outer whitespace and one matching pair of outer double quotes, without shell parsing. Invalid manual submissions preserve their original typed form, show an associated inline error, and restore input focus once pending/disabled state clears. Unrelated state snapshots must not overwrite a dirty draft, and an unmounted input must not apply a late picker result.

Production uses Tauri's dialog plugin; local development uses the same-origin loopback `pickPath` request. Its `{path}` response belongs to neither analysis nor combat state, and cancellation returns null. The backend serializes pickers on a dedicated STA, posts cancellation back to that STA, closes on timeout or parent EOF, and never uploads or executes a selected file. Selecting a combat executable does not launch or connect it. The development Windows picker sets per-monitor v2 awareness before COM or HWND creation and restores its prior thread context after normal, cancelled or failed cleanup. A pre-cancelled request leaves the context untouched. Production Tauri already initializes per-monitor v2 awareness; its dialog path is unchanged.

1. **角色库** discovers plausible installations and saves. Reading is explicit. Multiple characters require selection; do not claim the selected character is the active one in the game.
2. **配装工坊** shows saved-loadout main-skill DPS, default-attack DPS and health without calibration. Skill, difficulty and goal stay visible. Default weapon attack is a real selection with an empty record. Missing saved attacks remain unavailable with a reason.
3. **开始分析** uses the existing 180-second budget, ten candidates and 4,000 samples. These are implementation defaults, not extra form fields. Results open **方案对比**; cancellation must not label incomplete candidates as finished results.
4. **刷新角色** rereads disk, retains the selected identity when present and clears temporary buffs and measured inputs. A source change cannot keep an old character valid under a new path label.

The legacy Search enum is an analysis compatibility route. Unavailable workspaces may show an actionable empty state. Workspace state stays in the desktop session: local paths, unsaved edits and transient result selections are not shareable URL state. Render the bounded equipment/candidate datasets in full; the changed-only filter has a clear no-change state.

## Combat workflow and recovery

实战工具 is the fourth workspace. Switching to it neither launches nor connects to a game and does not depend on an imported analysis character. Hide the analysis-character chip here: the analyzed disk save and the live single-player character are independent identities. Do not replace analysis data, cached DPS or saved-loadout freshness with combat telemetry.

The nine features form one ungrouped responsive grid in this stable order: 无限生命 including armor/resistance protection, 无限蓝量 preserving skill reservations, 一击必杀, 移动速度, 最大攻击速度, 最大施法速度, 技能无冷却, 自动加血, 自动回蓝. Category headings and wrappers are removed. Use auto-fit columns with a 280 px target minimum bounded by 100% of available width, zero grid gaps and full-width separators; narrow layouts naturally reach one column. Keep DOM, keyboard and shortcut order consistent across column counts. This is a layout change only: labels, help Tooltip/Dialog, Switch/RadioGroup semantics and state/commands are unchanged. On first use nine switches start off and movement defaults to 2X. Thereafter the nine enabled choices and 2X/4X/8X/16X multiplier persist atomically in combat-settings.json. Choosing a multiplier never implicitly enables movement. Changing the multiplier while movement is active updates that choice without enabling other effects.

The executable path is a separate combat preference in `%LOCALAPPDATA%/GrimDawnOptimizer/combat-settings.json` (or the isolated data directory). If that preference does not yet exist, normal startup may read the legacy CairnCompanion path without modifying the legacy file; isolated startup never imports it. Selection validates Grim Dawn.exe plus adjacent Game.dll and Engine.dll and preserves the previous value after cancellation or rejection. Path selection alone never executes a program. Launch remains explicit. Auto-connect is enabled by default and can be disabled with a labeled Switch; it waits for the one process matching the saved executable and never starts the game. Manual disconnect pauses automatic connection for this app session until manual connect or toggling auto-connect on again. An unsuccessful automatic attempt is not retried into the same process; a chosen executable must match the connected process. Do not guess between multiple running games. Disable path changes while connecting or connected. The x64 client's working directory is the main installation directory.

Connection status must distinguish 未连接, 正在连接, 连接失败, 已连接 with architecture, 等待进入角色, 多人模式/已停用, 游戏未刷新, 组件检查失败 and 连接中断. Feature switches edit remembered choices even while disconnected. Game effects require a connected, fault-free single-player character and a fresh game heartbeat (less than three seconds). Show 已记住，等待单人角色 for remembered enabled choices that cannot yet apply. A requested switch is not an acknowledgment: show 待确认 for an unacknowledged enable and 关闭中 for an unacknowledged disable, and associate readable state/help with the control. Long errors and paths remain available by keyboard/click, not only a hover tooltip.

Strengthened integration behavior deliberately differs from the original UI: entering multiplayer, losing the character or expiring the heartbeat clears requested effects. Returning to valid single-player readiness reapplies the current remembered choices. Disconnect, process exit, runtime fault, backend transport disposal and application shutdown clear current game requests while preserving those choices. A new session starts with zero live flags, then applies choices only after readiness is confirmed. 全部关闭 and Ctrl+Alt+F12 also clear remembered enables; emergency off remains effective if the preference file cannot be saved. Analysis busy state does not block combat disable-all/disconnect, and combat work does not invalidate or relabel analysis results.

Ctrl+Alt+F1–F9 follow visible feature order and are global only while connected. They share the same availability gate as the switches. Ctrl+Alt+F12 disables all without requiring a usable character; the visible 全部关闭 action remains reachable. Unregister shortcuts on disconnect/shutdown and report registration conflicts without disabling UI alternatives. Typing and navigation in other workspaces must not cause duplicate shortcut dispatch.

Errors cover invalid/missing executable or adjacent DLLs, unreadable preferences, game not running, selected/running path mismatch, multiple processes, unsupported architecture, permissions, unsupported Game.dll hash, old loaded bridge, missing helper files, protocol mismatch, helper failure, timeout and runtime fault. Keep the original exact 1.3.1.1 build-hash compatibility gate; do not claim arbitrary version support. Explain restart where an older loaded bridge or runtime fault requires it.

Automatic potions use the original R/E potion actions, actual recovery, missing resource, remaining charges and native skill status. A spent charge's replenishment countdown does not block another available charge: statuses 1 and 3 are eligible only with a positive remaining charge count; other statuses and exhausted charges block automatic attempts. The original activation path still enforces game restrictions. Mana deficit excludes reserved energy. They operate only on an available living character with progressing, unpaused game time while the game is foreground, checking every 250 ms and attempting each resource at most once per 500 ms. They do not send keys to unrelated windows. The original 0.6.0 and 1.0.24 charge-fix evidence is binary inspection and x86/x64 simulation; it is not a verified live potion session. See docs/potion-charges.md.

The development loopback/same-origin transport exposes the real combat service rather than a pretend connection. This integration's initial verification is restricted to offline states and controlled test doubles; no launch, game attach or injection is implied by browser preview or static tests. Record any actual game validation separately.

## Correctness and input state

- Temporary buffs default off and clear on reload. They represent the compared moment, not combat uptime; source and weapon eligibility are rechecked per candidate.
- Skill, goal, difficulty, buff, duration, target count and debuff changes invalidate candidates. Main-skill changes also rebuild the preview.
- Equipment-granted attacks resolve sources/levels per candidate. Missing or incompatible attacks never silently become default attacks.
- Analysis freshness checks trigger reload/review or result rejection when disk saves change. Analysis cannot observe unsaved in-game equipment; combat telemetry is independent and does not substitute for a saved-loadout refresh.
- Legacy calibration remains for regression coverage; normal analysis ignores/clears it. Measured single-item values never fit the model.
- Backend panel DPS formatting uses `floor(raw + 0.5)` and remains fully visible. Combat output and survival are labeled separately.
- Coverage distinguishes panel, combat and survival impact. A concise limitation or disclosure entry remains discoverable; details expand. No warning is not a universal accuracy guarantee.
- Slot changes compare item and component/augment/completion identity, including attachment-only changes.
- Command replies/events carry a session identity and monotonic revision. Older snapshots and retired-session responses cannot restore stale values.
