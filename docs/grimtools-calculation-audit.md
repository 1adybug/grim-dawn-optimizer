# GrimTools 装备、技能与属性计算核对

核对日期：2026-11-11。参考页面当时标注 **1.3.1.0**；本项目仍从用户选择的本机游戏数据库读取装备和技能，不将这个网页版本当作所有本机安装的版本。DPS 的验收依据继续采用游戏面板观察值。

## 参考与复现

参考 [GrimTools 计算器](https://www.grimtools.com/calc/) 及其公开的 [计算器脚本](https://www.grimtools.com/calc/calc.js?1794027643)、[数据库脚本](https://www.grimtools.com/db/itemdb/itemdb.js?1794027643)。仅核对数据、公式和行为，没有在项目内复制或执行其应用代码。

`tests/GrimDawnOptimizer.Tests/Fixtures/grimtools-reference.json` 保留所用版本、来源 URL、完整下载文件 SHA-256，以及少量数值和数学公式。计算器脚本哈希为 `4ED417E8A7D97AAD66065EF4238BC08BE9F98C0015E889AD243CC08C46C2D5CE`，数据库脚本哈希为 `06D0883E9EF1D512153072ADA7B2CE3077D1DC467B6B9745E242A968299E8AFE`。完整第三方文件只保存在忽略的 `artifacts/grimtools-audit/reference/`，不随应用发布。

重新采集参考：

```powershell
python tests/reference/capture-grimtools.py
```

若站点拒绝 Python HTTP 客户端，可用 `Invoke-WebRequest` 下载上述页面和两个脚本，分别保存为参考目录中的 `calc.html`、`calc.js`、`itemdb.js`，再运行 `python tests/reference/capture-grimtools.py --offline`。脚本只解析指定的静态对象和数值，不执行下载的 JavaScript。更新参考后需审查差异，不应直接用新快照覆盖旧版本的验收结论。

## 逐项结果

| 范围 | 核对结果与处理 | 验证 |
| --- | --- | --- |
| 装备随机词条 | 保留本机数据库和实物 Seed 重放。GrimTools 默认平均值不代替实物结果；未支持的随机字段继续回退并提示 | 既有种子、抗性上限、概率词条和武器本地伤害回归 |
| 平伤、百分比与区间 | 修正零下限区间被当作最大值的问题，例如 `0–90` 均值为 45；固定值仍保留全量。基础元素武器伤害按三类平分 | 新增三类区间用例；既有全伤害、DoT 与本地武器用例 |
| 伤害转换 | 补齐 `Elemental`：作为来源时火/冰/电各按完整转换率处理，作为目标时转换量三等分；仍沿用技能先于装备、转换一次及超额归一化 | 元素转毒、物理转元素及与直接转火竞争；未知类型/额外未支持槽位会提示 |
| 护甲部位 | 修正直接相加。头/肩/胸/手/腿/脚的参考权重是 15/15/26/12/20/12；运行时优先读取本机 `combatformulas.dbr` | 六部位不同护甲、缺部位、自定义数据库权重 |
| 腰带与附件护甲 | 腰带和全局护甲作用于各部位；附件 `defensiveBonusProtection` 仅作用于宿主部位，区别于全局 `defensiveProtection` | 腰带、护甲组件、全局护甲组件分开核对 |
| 护甲吸收 | `基础吸收 × (1 + 加成/100)`，并封顶 100%；基础值读取 `gameengine.dbr`。70% 基础加 20% 吸收应为 84%，原实现为 90% | 参考基础 70%、加成、封顶 |
| 物理承伤 | 每部位分别按 `伤害 − min(伤害, 护甲) × 吸收率` 计算，再加权；避免高护甲在 70% 吸收时错误消除全部伤害 | 高于/低于护甲的命中、混合部位；未装备护甲的部位不获得护甲吸收 |
| 盾牌格挡 | 格挡加成按百分点相加，格挡量按百分比放大；不再把盾牌基础格挡概率当成格挡量的触发概率。没有盾牌时不产生格挡 | 35% 基础 +20 → 55%；1000 格挡量 +25% →1250，旧实现误算 437.5；卸盾回归 |
| 套装阈值 | 相同基础记录的两件实物只算一个不同部件，普通词条仍分别相加；属性需求、套装授予/加级来源、搜索签名使用相同规则 | 两枚相同套装戒指不能解锁第二件奖励；既有多阈值回归 |
| 技能等级 | 装备加级受 `skillUltimateLevel`（缺失时 `skillMaxLevel`）限制；不增加专精条、变异技能和信仰等级；按等级选数组时保留标量字段 | 参考战争伤痕 8/18 级、专精/三类变异/信仰、混合标量/数组 |
| 装备技能修正 | 同一个修改记录来自两件装备时分别叠加；卸下一件会移除一份。武器伤害百分比、正负冷却与能耗修正加到目标技能；子技能按自身等级、装备修改记录按 1 级取值 | 双戒指主动攻击/常驻被动；150% 基础 +20% 子技能 +2×25% 装备 →220% |
| 常驻、临时与武器资格 | 保留已有根技能激活、临时增益显式选择、授予来源和候选武器资格规则；没有把网页的理论 Buff 开启状态当作存档实况 | 既有常驻、临时、授予技能、武器条件回归 |
| 体格/灵巧/精神 | 平值后应用百分比，派生生命/能量不重复计算存档已包含的购点收益；本机属性增量和伤害公式与参考一致 | 同时改变三属性及百分比的独立预期值 |
| OA/DA、直接伤害/DoT 属性收益 | 现有 OA/DA 公式与参考一致；灵巧的直接伤害除数245、持续伤害215，精神的直接伤害215、持续伤害200分别核对，保留各自系数 | OA/DA 与四类属性伤害收益回归 |
| 生命/能量回复、预留 | 保留本机玩家资源公式和固定能量预留，不以 GrimTools 的展示或平均装备值重设系数 | 冻结真实存档的回复与 DPS 对照 |
| 抗性与难度 | 保留逐类型难度惩罚、封顶与超抗语义；元素抗性加到每个元素而非三等分。补齐已识别的元素抗性上限字段映射；后者未在本次网页实际数据中发现，仅作解析边界回归 | 既有难度/抗性回归，新增三元素与全抗上限组合 |
| 未验证字段 | `characterLifeMultModifier` 不再冒充普通生命百分比；明确列为未支持，等待独立核实玩家叠加规则 | 未验证生命倍率的诊断回归 |

计算中保留原始精度，不提前照搬网页各格的整数格式。最终显示与实测应采用相同的舍入语义。

## 尚不能宣称全面精确的部分

这次核对覆盖上述规则及回归输入，不构成所有职业、所有 DLC 词条和所有技能的全量认证。新内容中的独立生命倍率、专属预留减免、部分持续耗能、治疗/控制、触发覆盖率与特殊武器池回调仍需要游戏证据；未支持项继续显示诊断。GrimTools 自己也说明装备平均值可能不同于实物，且双持远程 APS 存在边界，见 [作者 FAQ](https://forums.crateentertainment.com/t/grimtools-build-calculator/38040)。本项目已有游戏面板依据的动画攻速和双枪规则继续保留。
