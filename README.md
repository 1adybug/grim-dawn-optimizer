# Grim Dawn Optimizer

一个面向《恐怖黎明》的离线配装分析器与单人实战工具。分析从角色、背包、个人仓库和对应模式的共享仓库只读获取装备，计算面板 DPS 并搜索最佳候选；独立的“实战工具”在明确连接后修改当前游戏会话内存，不直接编辑存档文件。

> 当前是可运行的工程版，**尚未正式宣告 1.3.x /《阿斯特卡恩之牙》真实存档兼容**。正式兼容声明仍需按下文清单在普通、专家真实角色上验收。

## 已实现

- `Tauri 2 + React + TypeScript + shadcn/ui` 桌面界面，复用 `.NET 8` 存档与计算内核。当前支持 Windows x64，同时发布安装版 EXE 与包含本地计算程序和辅助组件的单文件便携 EXE。
- 使用指定的 shadcn 预设 `b6HGdE1wo`：Rhea 风格、neutral 基础色、绿色主色，本地 Inter Variable / Noto Sans SC Variable 字体；顶部文字下划线页签、连续分隔线和紧凑装备表格沿用当前简洁风格。桌面窗口使用 Windows 原生标题栏，最小化、最大化/还原、关闭按钮位于右上角；浏览器预览不显示这些窗口按钮。
- “角色库”“配装工坊”“方案对比”“实战工具”四个工作区；支持跟随系统、浅色、深色及系统高对比模式。实战连接、功能状态与配装分析分别管理；自动连接在后台工作，不依赖当前页签，并可关闭。
- 自动发现正在运行的游戏安装、Steam、Steam Cloud、GOG/本地文档路径，并可手动选择目录。启动及每次导入时重新发现；优先保留本次明确手选，其次选择唯一正在运行的安装，再使用最近一次目录。存档优先采用游戏 `cloudSaving` 设置能够明确确定的来源，多 Steam 账户时不猜测当前账户。
- 只读解析 `player.gdc`、`transfer.gst` / `transfer.gsh`、`ARZ`、`ARC`、中文/英文标签；数据库按输入文件 SHA-256 写入可删除的 SQLite 缓存。
- 为每个实物构造稳定 ID，保留词缀、随机种子、组件、增幅、完成奖励、来源页和坐标；防止同一实物重复装备。
- 等级/属性需求、双手武器、副手、双戒指、套装阈值、伤害转化、抗性削减、OA/DA、暴击、攻速、护甲、抗性/超抗、闪避、格挡、反伤、回复和吸血的确定性模型。反伤按同级 BOSS 的命中、来袭频率、护甲和抗性折算；吸血按同级 BOSS 的吸血抗性折算。属性需求按可实际执行的穿戴顺序验证，装备本体可互相提供属性和需求减免，但组件、增幅与完成奖励不参与解锁；无起点的循环依赖方案会被排除。
- 合法附件变体、交互签名分组、Pareto 剪枝、武器优先且按槽位公平分时的多样性 Beam Search、一槽/两槽局部搜索和多起点扰动。Beam 扩展、完整候选、无镶嵌复算及 Monte Carlo 自动按逻辑处理器并行，最多使用 16 个工作线程；局部扰动搜索保持顺序执行。
- 按角色当前等级从游戏数据库汇总 BOSS 生命、护甲、抗性及战斗能力平均值；敌人护甲实际参与物理伤害与击杀时间计算。
- 装备本体与其当前组件/增幅分离计算；角色已拥有的附件（含已镶嵌附件及组件完成奖励）只会用于游戏数据库标记为兼容的槽位和武器类别。
- 推荐结果为组件和增幅分别显示首选与备选获取方式：除“已镶嵌”外会尽量给出两个具体来源，优先选择不同来源类别，不足时补充同类别的第二个位置；散装附件给出背包/个人仓库/共享仓库坐标，装备原有附件简单标为“已镶嵌”，组件配方指向铁匠，增幅指向阵营及所需声望。方案中的装备不会被当作其他装备的附件来源，没有方案外可执行来源的附件组合不会参与推荐。
- 每个候选同时显示“含组件/增幅、未计护甲抗性”和“仅装备本体、未计护甲抗性”DPS，便于先换装备后在游戏面板中核对；面板对照值排除 WPS 与随机触发，BOSS 实战 DPS 则计入它们。
- 游戏目录和存档目录各自只记住最近一次路径，不保存多条选择历史，也不显示历史下拉或删除记录操作。再次成功应用路径时替换该类最近值；失败输入和取消选择不改写已保存值。旧多条记录会迁移为每类一项，优先保留最后使用值。
- 游戏目录、存档目录和实战游戏程序均可直接输入路径，点击“使用”或按 Enter 应用；“浏览”打开系统文件夹/文件选择窗口，确认后应用，取消保留未应用的输入。路径验证失败会保留输入并显示错误；仅选择游戏程序不会启动或连接游戏。
- 分析导入读取已保存到磁盘的角色和装备，不读取游戏进程内尚未保存的装备状态。换装或切换武器组后，先让游戏保存，再“刷新角色”；刷新保留仍存在的所选角色，并清空临时增益。开始分析前检查存档是否改变，避免继续使用过期装备。分析不会自动识别或切换为游戏当前活动角色。
- 技能与信仰采用存档中已投入、已启用的等级作为固定构筑基础；支持识别当前双持构筑的副手武器。
- 自动使用最多 180 秒搜索、返回 10 个候选，并以固定种子进行 4,000 次抽样复核；显示进度并支持取消。
- 载入后立即根据本机游戏数据、已落盘存档、装备种子和当前附件显示主攻面板 DPS、默认攻击 DPS 与生命，无需填写实测值。正常分析不使用历史校准输入。
- 可明确选择默认武器攻击、已学习技能或装备授予的主攻。授予技能随每套候选的来源、授予等级和武器条件重新计算；来源卸下或所选技能已不可用时显示原因，不会悄悄改算默认攻击。
- `schemaVersion: 7` 的本地 JSON 方案；程序无遥测；配装分析保持离线，安装版可从 GitHub 自动检查、下载并安装签名更新，也可关闭自动检查。旧方案自动迁移，目标难度默认为普通。
- 构筑参数支持普通（新手）、老兵、精英、终极的单人战役难度。1.0.17 按玩家提供的游戏菜单截图固定伤害/生命预设，以普通为基准：普通 +0%/+0%，老兵 +15%/+140%，精英 +21%/+270%，终极 +30%/+530%。生命倍率作用于怪物自身生命和技能生命加成计算完成后的结果；数据库里的难度生命、伤害和攻速修正不再重复叠加。怪物 OA/DA、护甲和抗性仍读取本机数据库。专家角色（永久死亡）与战斗难度分别显示。
- 难度降抗固定按类型应用：精英的火/冰/电/酸毒/穿刺 −25 个百分点；终极这五类 −50，活力/虚化/混乱/流血 −25；物理不扣难度抗性。菜单概括的“玩家抗性”不会被扩展为所有抗性统一扣减。掉落与经验加成仅展示，不参与战斗评分。
- 可设置整场生效的怪物额外伤害加成和逐类型玩家降抗；降抗按百分点扣除，先扣难度惩罚与额外降抗、再限制抗性上限。结果展示战斗中的玩家抗性；修改难度或 Debuff 后会清除旧结果，需重新优化。
- 方案对比提供单件换装对照：固定其余当前装备，使用候选物品已有的组件和增幅，计算面板 DPS、属性与抗性的增减；单换不合法或附件未解析时显示原因。可填写游戏实测值查看偏差和增减方向不符，不会自动据此修改优化模型。
- 已生效的常驻技能及其修正按实际等级扣除固定能量预留，持续实战使用扣除后的可用能量；最大能量与角色面板 DPS 不受该预算折算影响。专属预留减免仍保留未支持提示，回复与触发覆盖率的边界见下文。

1.0.21 补齐游戏数据库中的玩家能量与生命回复公式，按每套候选的完整属性重新计算。原装、卸右戒指、虚空风暴头盔及神射手外衣的能量回复分别与游戏的 15.57、15.02、23.34、10.16 一致；神射手外衣经过游戏重启后仍为 10.16，恢复原装回到 15.57。没有使用实测值拟合系数。此前八组无校准面板 DPS 样本继续通过回归。实际生效技能含尚未完整支持的持续耗能时仍明确提示实战预算缺项。规则、输入身份和验证范围见 [面板 DPS 实测报告](docs/panel-dps-validation.md)。

## 自动分析与单件对照

1. 在“角色库”确认游戏与存档目录，载入并选择实际角色。
2. 在“配装工坊”查看当前主攻、默认攻击 DPS 和生命，选择主攻技能、实际难度及“均衡／输出优先／生存优先”目标。
3. 需要时展开“临时增益”或“特殊战斗场景”；临时增益默认关闭，离线存档不能判断游戏当前的短时效果。
4. 点击“开始分析”，完成后在“方案对比”查看替换位置、附件来源与单件差异。

修改主攻、目标、难度或战斗状态后，旧结果会失效，需重新分析。游戏内配装已经改变时，先让游戏保存，再刷新角色；所选技能已被洗掉或授予来源消失时，会提示不可用并阻止分析，直到选择有效主攻。

“单件换装对照”里的抗性是无临时降抗且封顶后的面板值，“战斗中玩家抗性”则计入设定的 Debuff。单件预测与整套推荐使用的附件可能不同。可选实测输入只用于当前结果的误差对照，重新分析后清空，不参与数值拟合。

## 实战工具

“实战工具”只合并 `grim-dawm-tool` 的当前游戏控制功能，沿用本项目的控件和分隔线布局；九项功能不分组，按窗口宽度自动换列，分隔线延伸到两边。它不包含已移除的任务指引、独立护甲开关或存档编辑。

| 快捷键 | 功能 |
|---|---|
| Ctrl+Alt+F1 | 无限生命，同时启用当前会话的护甲与抗性防护 |
| Ctrl+Alt+F2 | 无限蓝量，保留技能预留 |
| Ctrl+Alt+F3 | 一击必杀 |
| Ctrl+Alt+F4 | 移动速度，2X / 4X / 8X / 16X |
| Ctrl+Alt+F5 | 最大攻击速度 |
| Ctrl+Alt+F6 | 最大施法速度 |
| Ctrl+Alt+F7 | 技能无冷却 |
| Ctrl+Alt+F8 | 自动加血，调用 R 对应血药技能 |
| Ctrl+Alt+F9 | 自动回蓝，调用 E 对应蓝药技能 |

游戏程序路径、自动连接、九项功能开关与移动倍率使用 `schemaVersion: 1` 原子保存在 `%LOCALAPPDATA%\GrimDawnOptimizer\combat-settings.json`；没有该文件时可只读沿用旧工具 `%LOCALAPPDATA%\CairnCompanion\settings.json` 的路径，不写回旧设置。指定 `GRIM_DAWN_DATA_DIR` 的隔离运行不导入旧偏好。

选择 `Grim Dawn.exe` 后，默认开启的“自动连接”会等待对应游戏进程并连接，不会自动启动游戏；可以关闭自动连接，改用“连接”按钮。手动断开会暂停本次自动连接，点击连接或重新开启自动连接可恢复。首次使用时九个开关关闭、移动倍率为 2X；之后自动记住选择，重启、重连或单人角色恢复可用时应用。未连接时也能预先配置，界面显示“已记住，等待单人角色”；更改倍率不会自动开启移动速度。分析选择的存档角色与当前游戏角色是两个独立来源，不自动关联。

开关区分“已请求”和“游戏已确认”，未确认时显示待确认。多人模式、等待角色或游戏心跳过期会暂停当前效果请求，保留功能偏好，在有效单人角色恢复后重新应用；断开、游戏退出、运行时故障及关闭工具同样清除当前效果，不清除已保存偏好。已连接时 `Ctrl+Alt+F12` 不受角色可用状态限制；界面“全部关闭”也可随时关闭当前效果并清除记忆中的开启项，移动倍率保留。自动连接失败不会反复向同一游戏进程重试，可手动连接或重启游戏后重试。全局快捷键只在已连接时注册，冲突时仍可使用界面。

实战组件针对已适配的 1.3.1.1 `Game.dll` 完整 SHA-256 白名单，并区分 x86/x64；不匹配时停止连接。已加载旧版组件时需完全重启游戏。自动药水按实际回复量、缺失资源、剩余充能和技能状态判断；蓝量缺口扣除技能预留，只在游戏前台、未暂停且角色可用时触发。1.0.24 修复血药、蓝药在恢复充能期间漏用剩余充能的问题，继续使用游戏原生 R/E 技能执行，并保留每 250 毫秒检查、每种药水至少间隔 500 毫秒尝试的限制。双架构接口依据与模拟验证见 [自动药水充能说明](docs/potion-charges.md)，尚未完成真实游戏会话验证。

## 安装版更新

右上角“设置与关于”提供“自动检查更新”“自动下载并安装”和手动“检查更新”。安装版默认启动后检查，并每 6 小时检查 GitHub 正式版本；只有更高版本才会更新。默认自动下载并校验签名，在分析结束且实战工具断开后安装并重启。关闭自动检查后不再发起后台检查，也不自动安装，仍可手动检查和安装。更新偏好原子保存到本地 `update-settings.json`，重启后保留。设置损坏时暂停后台检查并显示修复提示。

便携版保持直接运行，通过 GitHub 手动下载新版，不会启动安装器。更新依赖 GitHub 网络可达；断网、下载失败或签名不符会显示错误并允许重试。

## 运行

开发环境需要 Windows、.NET 8 SDK、Node.js 24 LTS、Rust stable MSVC 工具链，以及 Visual Studio 的 C++ 桌面构建工具和 Windows SDK。WebView2 运行时用于桌面界面。项目不把 Tauri 的跨平台能力等同于已经支持 macOS/Linux。

```powershell
npm run setup
npm run dev
```

`npm run dev` 会准备自包含的 .NET 计算程序，再启动 Tauri。没有游戏也可以在“角色库”载入演示数据验证完整流程，无需填写面板 DPS。

只调试浏览器界面时，先准备本地计算程序，再启动开发服务：

```powershell
npm --prefix src/GrimDawnOptimizer.Desktop run engine:prepare
npm run dev:web
```

访问 `http://127.0.0.1:1420`。浏览器开发模式仍调用真实本地计算程序，通过仅限本机同源的开发接口通信；正式桌面包不开放这个 HTTP/SSE 接口。需要隔离测试偏好时，先设置 `$env:GRIM_DAWN_DATA_DIR` 为一个绝对目录。

生成 Windows 安装版与单文件便携 EXE（签名私钥只保存在本机或 CI Secret）：

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Join-Path $env:USERPROFILE ".tauri/grim-dawn-optimizer.key"
npm --prefix src/GrimDawnOptimizer.Desktop run tauri:build
npm --prefix src/GrimDawnOptimizer.Desktop run desktop:installer
npm --prefix src/GrimDawnOptimizer.Desktop run desktop:portable
```

安装版为 `artifacts/GrimDawnOptimizer-1.0.24-win-x64-setup.exe`。便携产物为 `artifacts/GrimDawnOptimizer-1.0.24-win-x64.exe`，下载后直接运行，无需安装或手动解压。启动器内嵌 Tauri 主程序、自包含 .NET 计算引擎、完整实战组件和许可证，校验后自动释放到 `%LOCALAPPDATA%\GrimDawnOptimizer\portable` 下的版本缓存目录；完整缓存会复用，损坏文件会修复。系统仍需具备 WebView2 运行时，计算与分析保持离线。

首次解析游戏数据库会较慢；缓存位于 `%LOCALAPPDATA%\GrimDawnOptimizer`，可以删除缓存并自动重建。优化方案、最近一次游戏/存档路径与 `ui-settings.json` 偏好也保存在该目录，清理时不要误删需要保留的配置。UI 偏好使用 `schemaVersion: 1` 并原子写入。

验证命令：

```powershell
npm run check
npm run build:web
dotnet test .\GrimDawnOptimizer.sln
python .\tests\desktop-bridge\smoke.py
python .\tests\desktop-bridge\trainer-smoke.py
python .\tests\desktop-bridge\portable-smoke.py
node .\tests\desktop-bridge\dev-transport.mjs
node .\tests\desktop-bridge\sse-backpressure.mjs
```

`python .\tests\desktop-bridge\smoke.py --complete` 还会等待完整的演示配装分析。协议测试使用临时配置目录，不改写实际用户偏好。`trainer-smoke.py` 明确禁止连接和启动命令，只验证离线状态、路径校验/持久化、分析并发与关闭恢复，不加载或执行测试路径中的占位文件。架构、对齐清单和已执行验证见 [Tauri 迁移说明](docs/tauri-migration.md)。

旧 WPF 工程与此前界面修改保留在 `src/GrimDawnOptimizer.App`，用于工作流回归与比较；共享视图模型由两个入口复用。需要运行旧入口时使用 `dotnet run --project .\src\GrimDawnOptimizer.App`。旧界面的设计与验收记录保存在 [WPF 设计存档](docs/legacy-wpf-design.md) 和 [WPF 交互存档](docs/legacy-wpf-ux.md)。

## 持续集成与发布

GitHub Actions 在提交到 `main`、创建或更新面向 `main` 的 Pull Request，以及手动运行时执行 .NET Release 构建/测试、Tauri 桌面构建和轻量 Rust 协议测试。缓存 npm、NuGet 和 Cargo 依赖；Tauri 只编译一次，随后封装并无窗口验证实际便携 EXE。

先等待 `main` 上对应提交构建成功，再推送与程序版本一致的标签。标签任务直接复用该提交已验证的构建产物，GitHub Release 同时提供安装版、便携版，以及自动更新需要的 `latest.json` 和安装器签名。例如：

## 评分与结果语义

评分只保留两个最终结果：计入目标防御后的实际 DPS，以及综合有效生命。DPS 对比在设定战斗时限内击杀 BOSS 所需的 DPS，并包含同级 BOSS 命中角色时触发的反伤；有效生命对比 BOSS 在同一时限内的原始伤害，并以“承受 DPS − 回复 − 对该 BOSS 的有效吸血”计算净承伤。武器、伤害词条、OA、命中、暴击、攻速、触发和反伤通过 DPS 生效；生命、十类抗性、护甲、吸收、DA、闪避、格挡、回复和吸血通过有效生命生效。

分析目标提供“均衡”“输出优先”和“生存优先”，输出与有效生命的相对权重分别为 1:1、2:1 和 1:2，不设置硬性最小值。承伤靶子把原有总伤害分配到物理、穿刺、火、冰、电、酸、活力、虚化、混乱和流血十种类型，使所有抗性都自然进入有效生命计算。

搜索结果只称“最佳候选”。时间预算内的 Beam Search 不是穷举，也不提供虚假的全局最优性差距；最终会对搜索得到的合法候选去重、按全局得分排序，并只对前 10 个执行无镶嵌复算与 Monte Carlo 复核。搜索可随时取消。

## 当前建模边界

目标难度需要手动选择，不推断存档中最后游玩的难度。截图预设是用户指定的近似模型，不宣称还原了游戏引擎内部倍率公式。来袭伤害是普通混合模板乘以截图难度倍率，再乘以手动额外增伤倍率；不额外叠加数据库的类型增伤和攻速。尚未还原具体 BOSS 技能循环、怪物属性对伤害的全部贡献、地图词缀、多人缩放与飞升模式。Debuff 输入表示持续生效的指定场景，暂不模拟触发覆盖率、不同类别降抗的叠加规则或动态战斗状态。缺少难度数据库时截图预设仍生效，其他缺失的怪物属性修正会提示。

伤害计算将装备上的“+% 所有类型伤害”与各伤害类型的百分比加成相加，只有“总伤害修正”单独相乘；所有类型伤害也参与装备等级缩放。面板 DPS 对照保留实际攻速，战斗时限内的能量不足只影响持续实战 DPS。固定能量预留和玩家回复公式已有换装实测对照；专属预留减免、部分持续技能耗能及触发覆盖率仍未完整支持，按来源保留警告。综合分较高不保证单换某件装备后面板 DPS 或每项抗性都提高。

第一版不计算宠物伤害、走位、投射物碰撞、动画取消和复杂手法循环。已按装备 Seed 重放游戏的 MINSTD 随机流、Jitter、缩放与取整顺序；遇到尚未建模、可能令随机序列错位的字段时会明确回退到期望值并降低置信度。装备中无法识别的技能修正或触发会保留、列出并降低置信度，不会被当作真实零贡献。没有面板缺项警告也不代表所有职业和换装都已实测。配方文件解析为保守的 best-effort；识别失败时仍可使用存档中的实物附件及铁匠基础配方，其他配方组件会被排除并给出警告。

## 真实存档验收清单

正式标注最新版本兼容前，需要在安装全部官方 DLC 的真实环境完成：

1. 普通角色：穿戴、背包、个人仓库与 `transfer.gst` 数量及来源逐项核对。
2. 专家角色：确认只合并 `transfer.gsh`，不混入普通共享仓库。
3. 抽查带随机词缀、组件、增幅、遗物完成奖励和 Asterkarn 新字段的物品。
4. 优化前后分别计算所有存档 SHA-256，确认字节完全不变。
5. 与游戏面板及训练假人记录核对主要属性、DPS 与承伤趋势。

实战原生组件使用 MinHook，完整许可随源码保留于 [LICENSES/MinHook-BSD.txt](LICENSES/MinHook-BSD.txt)。第三方来源与许可见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。
