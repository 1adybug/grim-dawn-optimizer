# Cairn Loadout Lab

一个面向《恐怖黎明》的离线装备构筑求解器。程序从角色、背包、个人仓库和对应模式的共享仓库读取装备，按“属性值 ÷ 同级 BOSS 基准 × 权重”的总分搜索最佳候选，并给出逐槽替换位置、期望 DPS、防御指标和固定种子的 Monte Carlo 区间。

> 当前是可运行的工程版。开发机没有安装游戏或真实存档，因此 **尚未正式宣告 1.3.x /《阿斯特卡恩之牙》真实存档兼容**。内置演示数据和自动化测试已通过；正式兼容声明仍需按下文清单在普通、专家真实角色上验收。

## 已实现

- `.NET 8 + WPF`、MVVM、Windows x64、自包含单文件发布。
- 自动发现 Steam、Steam Cloud、GOG/本地文档路径，并可手动选择目录。
- 只读解析 `player.gdc`、`transfer.gst` / `transfer.gsh`、`ARZ`、`ARC`、中文/英文标签；数据库按输入文件 SHA-256 写入可删除的 SQLite 缓存。
- 为每个实物构造稳定 ID，保留词缀、随机种子、组件、增幅、完成奖励、来源页和坐标；防止同一实物重复装备。
- 等级/属性需求、双手武器、副手、双戒指、套装阈值、伤害转化、抗性削减、OA/DA、暴击、攻速、护甲、抗性/超抗、闪避、格挡、回复和吸血的确定性模型。属性需求按可实际执行的穿戴顺序验证，装备本体可互相提供属性和需求减免，但组件、增幅与完成奖励不参与解锁；无起点的循环依赖方案会被排除。
- 合法附件变体、交互签名分组、Pareto 剪枝、武器优先且按槽位公平分时的多样性 Beam Search、一槽/两槽局部搜索和多起点扰动。
- 按角色当前等级从游戏数据库汇总 BOSS 生命、护甲、抗性及战斗能力平均值；敌人护甲实际参与物理伤害与击杀时间计算。
- 装备本体与其当前组件/增幅分离计算；角色已拥有的附件（含已镶嵌附件及组件完成奖励）只会用于游戏数据库标记为兼容的槽位和武器类别。
- 每个候选同时显示“含组件/增幅、未计护甲抗性”和“仅装备本体、未计护甲抗性”DPS，便于先换装备后在游戏面板中核对；面板对照值排除 WPS 与随机触发，BOSS 实战 DPS 则计入它们。
- 游戏目录和存档目录分别保存完整选择历史，并在下次启动时恢复最后使用项；下拉框中的删除只移除历史记录并阻止自动发现重新添加，不会删除磁盘文件，重新手动选择即可恢复。
- 技能与信仰采用存档中已投入、已启用的等级作为固定构筑基础；支持识别当前双持构筑的副手武器。
- 1–300 秒搜索预算（建议 60–180 秒）、Top 1–50、固定种子 500–10,000 次抽样、进度与取消。
- 运行优化前必须同时输入游戏面板中的“武器攻击 DPS”和当前所选主攻技能的目标无关 DPS：前者校准基础武器输出，二者差值校准技能附加部分。两项只用于本次角色载入，不写入方案，切换角色或主攻技能后会清空。武器基础速度、单双持动画系数和全局攻速在校准前独立计算。
- `schemaVersion: 5` 的本地 JSON 方案；程序无遥测、无自动更新、无网络请求。

## 运行

开发环境需要 Windows 和 .NET 8 SDK：

```powershell
dotnet test .\GrimDawnOptimizer.sln
dotnet run --project .\src\GrimDawnOptimizer.App\GrimDawnOptimizer.App.csproj
```

没有游戏也可以点击右上角“演示数据”验证读取与搜索界面；运行搜索前仍需手动输入两个正数的面板 DPS 测试值。

生成无需安装 .NET 运行时的便携包：

```powershell
dotnet publish .\src\GrimDawnOptimizer.App\GrimDawnOptimizer.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -o .\artifacts\win-x64
```

启动 `artifacts\win-x64\GrimDawnOptimizer.App.exe` 即可。首次解析游戏数据库会较慢；缓存位于 `%LOCALAPPDATA%\GrimDawnOptimizer`，可以安全删除并自动重建。方案也保存在该目录。

## 持续集成与发布

GitHub Actions 会在提交到 `main`、创建或更新面向 `main` 的 Pull Request，以及手动运行工作流时执行 Release 构建和全部测试。

推送以 `v` 开头的标签会在构建和测试通过后创建正式 GitHub Release，并附带 `GrimDawnOptimizer-<标签>-win-x64.zip` 便携包。例如：

```powershell
git tag v1.0.0
git push origin v1.0.0
```

所有 `v*` 标签都会创建正式版本，不会根据标签中的 `beta`、`rc` 或连字符自动标记为预发布版本。若同一标签的 Release 已经存在，工作流会保留现有 Release 和附件，不执行覆盖。

## 评分与结果语义

评分只保留两个互不重复的最终结果：计入目标防御后的实际 DPS，以及综合有效生命。DPS 对比在设定战斗时限内击杀 BOSS 所需的 DPS；有效生命对比 BOSS 在同一时限内的原始伤害。武器、伤害词条、OA、命中、暴击、攻速和触发只通过 DPS 生效；生命、九类抗性、护甲、吸收、DA、闪避和格挡只通过有效生命生效，不再重复加权。

属性权重界面固定显示“输出完成度”和“综合有效生命完成度”，不能新增、删除或改名，用户只调整两者的权重，不设置硬性最小值。承伤靶子把原有总伤害分配到物理、穿刺、火、冰、电、酸、活力、虚化和混乱九种类型，使所有抗性都自然进入有效生命计算。

搜索结果只称“最佳候选”。时间预算内的 Beam Search 不是穷举，也不提供虚假的全局最优性差距。

## 当前建模边界

第一版不计算宠物伤害、走位、投射物碰撞、动画取消和复杂手法循环。已按装备 Seed 重放游戏的 MINSTD 随机流、Jitter、缩放与取整顺序；遇到尚未建模、可能令随机序列错位的字段时会明确回退到期望值并降低置信度。武器攻击与主攻技能的两个面板 DPS 仍用于补偿技能、触发和动画层面的未建模差异。装备中无法识别的技能修正或触发会保留、列出并降低置信度，不会被当作真实零贡献。配方文件解析为保守的 best-effort；识别失败时只启用不要求配方的组件并给出警告。

## 真实存档验收清单

正式标注最新版本兼容前，需要在安装全部官方 DLC 的真实环境完成：

1. 普通角色：穿戴、背包、个人仓库与 `transfer.gst` 数量及来源逐项核对。
2. 专家角色：确认只合并 `transfer.gsh`，不混入普通共享仓库。
3. 抽查带随机词缀、组件、增幅、遗物完成奖励和 Asterkarn 新字段的物品。
4. 优化前后分别计算所有存档 SHA-256，确认字节完全不变。
5. 与游戏面板及训练假人记录核对主要属性、DPS 与承伤趋势。
