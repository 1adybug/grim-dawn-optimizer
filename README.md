# Grim Dawn Optimizer

一个面向《恐怖黎明》的离线装备构筑求解器。程序从角色、背包、个人仓库和对应模式的共享仓库读取装备，按“属性值 ÷ 同级 BOSS 基准 × 权重”的总分搜索最佳候选，并给出逐槽替换位置、期望 DPS、防御指标和固定种子的 Monte Carlo 区间。

> 当前是可运行的工程版，**尚未正式宣告 1.3.x /《阿斯特卡恩之牙》真实存档兼容**。正式兼容声明仍需按下文清单在普通、专家真实角色上验收。

## 已实现

- `.NET 8 + WPF + WPF UI 4.3`、MVVM、Windows x64、自包含单文件发布；界面采用原生 Fluent / Mica 外壳。
- 数据源、构筑、搜索与结果四个独立工作区；支持跟随系统、浅色和深色主题，并同步 Windows 强调色与高对比设置。
- 自动发现正在运行的游戏安装、Steam、Steam Cloud、GOG/本地文档路径，并可手动选择目录。启动及每次导入时重新发现；优先保留本次明确手选，其次选择唯一正在运行的安装，再使用历史目录。存档优先采用游戏 `cloudSaving` 设置能够明确确定的来源，多 Steam 账户时不猜测当前账户。
- 只读解析 `player.gdc`、`transfer.gst` / `transfer.gsh`、`ARZ`、`ARC`、中文/英文标签；数据库按输入文件 SHA-256 写入可删除的 SQLite 缓存。
- 为每个实物构造稳定 ID，保留词缀、随机种子、组件、增幅、完成奖励、来源页和坐标；防止同一实物重复装备。
- 等级/属性需求、双手武器、副手、双戒指、套装阈值、伤害转化、抗性削减、OA/DA、暴击、攻速、护甲、抗性/超抗、闪避、格挡、反伤、回复和吸血的确定性模型。反伤按同级 BOSS 的命中、来袭频率、护甲和抗性折算；吸血按同级 BOSS 的吸血抗性折算。属性需求按可实际执行的穿戴顺序验证，装备本体可互相提供属性和需求减免，但组件、增幅与完成奖励不参与解锁；无起点的循环依赖方案会被排除。
- 合法附件变体、交互签名分组、Pareto 剪枝、武器优先且按槽位公平分时的多样性 Beam Search、一槽/两槽局部搜索和多起点扰动。Beam 扩展、完整候选、无镶嵌复算及 Monte Carlo 自动按逻辑处理器并行，最多使用 16 个工作线程；局部扰动搜索保持顺序执行。
- 按角色当前等级从游戏数据库汇总 BOSS 生命、护甲、抗性及战斗能力平均值；敌人护甲实际参与物理伤害与击杀时间计算。
- 装备本体与其当前组件/增幅分离计算；角色已拥有的附件（含已镶嵌附件及组件完成奖励）只会用于游戏数据库标记为兼容的槽位和武器类别。
- 推荐结果为组件和增幅分别显示首选与备选获取方式：除“已镶嵌”外会尽量给出两个具体来源，优先选择不同来源类别，不足时补充同类别的第二个位置；散装附件给出背包/个人仓库/共享仓库坐标，装备原有附件简单标为“已镶嵌”，组件配方指向铁匠，增幅指向阵营及所需声望。方案中的装备不会被当作其他装备的附件来源，没有方案外可执行来源的附件组合不会参与推荐。
- 每个候选同时显示“含组件/增幅、未计护甲抗性”和“仅装备本体、未计护甲抗性”DPS，便于先换装备后在游戏面板中核对；面板对照值排除 WPS 与随机触发，BOSS 实战 DPS 则计入它们。
- 游戏目录和存档目录分别保存完整选择历史；没有明确的运行中来源时恢复最后使用项。下拉框中的删除只移除历史记录并阻止自动发现重新添加，不会删除磁盘文件，重新手动选择即可恢复。
- 导入读取已保存到磁盘的角色和装备，不读取游戏进程内尚未保存的状态。换装或切换武器组后，先让游戏保存，再重新导入；导入后需要确认所选角色，程序不会自动识别游戏当前活动角色。
- 技能与信仰采用存档中已投入、已启用的等级作为固定构筑基础；支持识别当前双持构筑的副手武器。
- 1–300 秒搜索预算（默认 180 秒）、Top 1–50（默认 10）、固定种子 500–10,000 次抽样（默认 4,000）、进度与取消。
- 默认直接根据本机游戏数据、已落盘存档、装备种子与所选技能计算面板 DPS，无需填写实测值。搜索页的“使用 DPS 校准（可选）”默认关闭；只有主动开启后才使用手填值。默认攻击、纯法术和无法可靠拆分的技能使用单点校准；明确包含武器伤害的可靠技能额外要求“默认武器攻击 DPS”，分别校准武器与技能附加部分。两个模型锚点过近时回退单点校准。开关与输入均不写入方案，重载角色或切换主攻技能后清空；关闭时旧输入不影响计算。角色属性校准仍独立可选。
- `schemaVersion: 7` 的本地 JSON 方案；程序无遥测、无自动更新、无网络请求。旧方案自动迁移，目标难度默认为普通。
- 构筑参数支持普通（新手）、老兵、精英、终极的单人战役难度。1.0.17 按玩家提供的游戏菜单截图固定伤害/生命预设，以普通为基准：普通 +0%/+0%，老兵 +15%/+140%，精英 +21%/+270%，终极 +30%/+530%。生命倍率作用于怪物自身生命和技能生命加成计算完成后的结果；数据库里的难度生命、伤害和攻速修正不再重复叠加。怪物 OA/DA、护甲和抗性仍读取本机数据库。专家角色（永久死亡）与战斗难度分别显示。
- 难度降抗固定按类型应用：精英的火/冰/电/酸毒/穿刺 −25 个百分点；终极这五类 −50，活力/虚化/混乱/流血 −25；物理不扣难度抗性。菜单概括的“玩家抗性”不会被扩展为所有抗性统一扣减。掉落与经验加成仅展示，不参与战斗评分。
- 可设置整场生效的怪物额外伤害加成和逐类型玩家降抗；降抗按百分点扣除，先扣难度惩罚与额外降抗、再限制抗性上限。结果展示战斗中的玩家抗性；修改难度或 Debuff 后会清除旧结果，需重新优化。
- 运行优化页新增 31 项可选角色属性校准：最大生命/能量、OA/DA、攻速/施法速度、护甲/吸收率、生命/能量回复、全局吸血，以及十类含超抗抗性和抗性上限。空白继续自动计算，非法输入阻止运行。数值仅存在当前会话，切换角色、重载存档或切换难度会清空。
- 最佳候选页新增单件换装对照：固定其余当前装备，使用候选物品已有的组件和增幅，计算面板 DPS、属性与抗性的增减；单换不合法或附件未解析时显示原因。可填写游戏实测值查看偏差和增减方向不符，不会自动据此修改优化模型。

1.0.18 已在双枪火焰打击构筑上完成五组无校准面板验证：全装备、分别卸下两枚戒指、卸下头盔及普通攻击，按游戏整数显示全部一致；独立进程重新载入后结果一致。具体输入身份、规则和未覆盖范围见 [面板 DPS 实测报告](docs/panel-dps-validation.md)。

## 属性校准与单件对照

先选实际游玩的难度，再到“运行优化”展开“角色属性校准”和“抗性、超抗与上限”。保持已载入的装备、武器组和常驻光环一致，在无临时 Buff、药水和降抗的状态读取面板。优先填写生命、OA、DA、攻速及抗性。面板抗性 80%、超抗 32% 时，含超抗项填写 112，上限填写 80；不要再次扣除难度惩罚。速度已封顶时需输入未封顶值，不清楚则留空。

模型在原配装上计算缺失的基础属性贡献，并在各候选中重新应用相应百分比加成；速度校准保留武器基础速度差异，抗性校准先还原难度前数值，战斗中再应用难度和 Debuff。这依赖“缺失基础贡献在换装后仍存在”的假设；装备技能等级、光环或未建模效果发生变化时仍可能产生误差，校准不保证换装预测完全准确。

“单件换装对照”里的抗性是无临时降抗且封顶后的面板值，顶部“战斗中玩家抗性”则计入设定的 Debuff。单件预测与整套推荐使用的附件可能不同。实测输入只用于当前结果的误差对照，重新优化后清空。游戏内配装已改变时，重新载入存档并重新填写校准值。

## 运行

开发环境需要 Windows 和 .NET 8 SDK：

```powershell
dotnet test .\GrimDawnOptimizer.sln
dotnet run --project .\src\GrimDawnOptimizer.App\GrimDawnOptimizer.App.csproj
```

没有游戏也可以在“数据源”工作区点击“演示数据”验证读取与搜索流程，默认无需填写面板 DPS。手动开启 DPS 校准后，按所选技能提示输入一个或两个正数的测试值。

生成无需安装 .NET 运行时的便携包：

```powershell
dotnet publish .\src\GrimDawnOptimizer.App\GrimDawnOptimizer.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -o .\artifacts\win-x64
```

启动 `artifacts\win-x64\GrimDawnOptimizer.App.exe` 即可。首次解析游戏数据库会较慢；缓存位于 `%LOCALAPPDATA%\GrimDawnOptimizer`，可以安全删除并自动重建。优化方案、目录历史与 `ui-settings.json` UI 偏好均保存在该目录，但彼此独立；UI 偏好文件使用 `schemaVersion: 1` 并以原子替换方式写入。

## 持续集成与发布

GitHub Actions 会在提交到 `main`、创建或更新面向 `main` 的 Pull Request，以及手动运行工作流时执行 Release 构建和全部测试。

推送以 `v` 开头的标签会在构建和测试通过后创建正式 GitHub Release，并附带自包含的单文件程序 `GrimDawnOptimizer.App.exe`。例如：

```powershell
git tag v1.0.0
git push origin v1.0.0
```

所有 `v*` 标签都会创建正式版本，不会根据标签中的 `beta`、`rc` 或连字符自动标记为预发布版本。若同一标签的 Release 已经存在，工作流会保留现有 Release 和附件，不执行覆盖。

## 评分与结果语义

评分只保留两个最终结果：计入目标防御后的实际 DPS，以及综合有效生命。DPS 对比在设定战斗时限内击杀 BOSS 所需的 DPS，并包含同级 BOSS 命中角色时触发的反伤；有效生命对比 BOSS 在同一时限内的原始伤害，并以“承受 DPS − 回复 − 对该 BOSS 的有效吸血”计算净承伤。武器、伤害词条、OA、命中、暴击、攻速、触发和反伤通过 DPS 生效；生命、十类抗性、护甲、吸收、DA、闪避、格挡、回复和吸血通过有效生命生效。

属性权重界面固定显示“输出完成度”和“综合有效生命完成度”，不能新增、删除或改名，用户只调整两者的权重，不设置硬性最小值。承伤靶子把原有总伤害分配到物理、穿刺、火、冰、电、酸、活力、虚化、混乱和流血十种类型，使所有抗性都自然进入有效生命计算。

搜索结果只称“最佳候选”。时间预算内的 Beam Search 不是穷举，也不提供虚假的全局最优性差距；最终会对搜索得到的合法候选去重、按全局得分排序，并只对 Top N 执行无镶嵌复算与 Monte Carlo 复核。搜索可随时取消。

## 当前建模边界

目标难度需要手动选择，不推断存档中最后游玩的难度。截图预设是用户指定的近似模型，不宣称还原了游戏引擎内部倍率公式。来袭伤害是普通混合模板乘以截图难度倍率，再乘以手动额外增伤倍率；不额外叠加数据库的类型增伤和攻速。尚未还原具体 BOSS 技能循环、怪物属性对伤害的全部贡献、地图词缀、多人缩放与飞升模式。Debuff 输入表示持续生效的指定场景，暂不模拟触发覆盖率、不同类别降抗的叠加规则或动态战斗状态。缺少难度数据库时截图预设仍生效，其他缺失的怪物属性修正会提示。

伤害计算将装备上的“+% 所有类型伤害”与各伤害类型的百分比加成相加，只有“总伤害修正”单独相乘；所有类型伤害也参与装备等级缩放。面板 DPS 对照保留实际攻速，战斗时限内的能量不足只影响持续实战 DPS。两者可能存在取舍，综合分较高不保证单换某件装备后面板 DPS 或每项抗性都提高。

第一版不计算宠物伤害、走位、投射物碰撞、动画取消和复杂手法循环。已按装备 Seed 重放游戏的 MINSTD 随机流、Jitter、缩放与取整顺序；遇到尚未建模、可能令随机序列错位的字段时会明确回退到期望值并降低置信度。只有主动开启可选 DPS 校准时，才把主攻技能面板 DPS 作为校准锚点；技能记录足以可靠分离武器伤害时，再加入默认武器攻击 DPS 作为第二锚点。校准只能补偿当前基线，不能证明换装预测准确。装备中无法识别的技能修正或触发会保留、列出并降低置信度，不会被当作真实零贡献。配方文件解析为保守的 best-effort；识别失败时仍可使用存档中的实物附件及铁匠基础配方，其他配方组件会被排除并给出警告。

## 真实存档验收清单

正式标注最新版本兼容前，需要在安装全部官方 DLC 的真实环境完成：

1. 普通角色：穿戴、背包、个人仓库与 `transfer.gst` 数量及来源逐项核对。
2. 专家角色：确认只合并 `transfer.gsh`，不混入普通共享仓库。
3. 抽查带随机词缀、组件、增幅、遗物完成奖励和 Asterkarn 新字段的物品。
4. 优化前后分别计算所有存档 SHA-256，确认字节完全不变。
5. 与游戏面板及训练假人记录核对主要属性、DPS 与承伤趋势。

第三方来源与许可见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。
